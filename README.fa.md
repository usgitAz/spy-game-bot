# ربات تلگرام SpyFall (بازی جاسوس)

ربات بازی کلمه‌ای گروهی برای تلگرام (رابط کاربری فارسی). یک نفر **جاسوس** است و کلمهٔ مخفی را نمی‌داند؛ بقیه می‌دانند. بازیکنان با سؤال، رأی و حدس سعی می‌کنند جاسوس را پیدا کنند — یا جاسوس کلمه را حدس بزند.

ساخته‌شده با **Python 3.12**، **aiogram 3** و **Redis**.

نسخهٔ لایو بات را می‌توانید در تلگرام استفاده کنید:

>نسخهٔ لایو بات را می‌توانید در تلگرام استفاده کنید: [@spyfallgamerobot](https://t.me/spyfallgamerobot)

> نسخهٔ انگلیسی همین سند: [README.md](README.md)

## قابلیت‌ها

### گیم‌پلی

- **بازی جدید در گروه** — دستور `/newgame` پنل تنظیمات را باز می‌کند (مدت دور، امکان دو جاسوس برای ۷ نفر به بالا).
- **لابی** — پیوستن، خروج، حذف بازی، قوانین، شروع وقتی تعداد بازیکن کافی باشد.
- **نقش‌ها** — به‌طور پیش‌فرض یک جاسوس (یا دو جاسوس در صورت فعال بودن و تعداد کافی بازیکن)؛ شهروندان کلمه را می‌بینند، جاسوس نه.
- **اقدامات حین دور**
  - دکمه «دیدن نقش من» (فقط برای همان کاربر به‌صورت هشدار خصوصی).
  - جاسوس می‌تواند **وسط دور** با ارسال **عیناً خود کلمه** (بدون متن اضافه) برنده شود.
- **رأی‌گیری** — بعد از تمام شدن تایمر دور، پنل رأی **از نو ارسال** می‌شود تا پایین چت بماند.
  - فقط بازیکنان داخل بازی می‌توانند رأی بدهند.
  - هر نفر یک رأی؛ رأی به خود مجاز نیست.
  - اعلام رأی در گروه.
  - اگر همه رأی دادند زودتر تمام می‌شود؛ در غیر این صورت مهلت رأی‌گیری اعمال می‌شود.
- **تساوی آرا** — اگر بیشترین رأی مساوی باشد، **دور دوم** فقط بین همان نفرات. اگر باز هم مساوی شد، بازی **مساوی** اعلام می‌شود.
- **اخراج جاسوس** — جاسوس فرصت کوتاهی برای حدس دقیق کلمه دارد؛ درست → برد جاسوس، غلط → برد شهروندان.
- **اخراج شهروند** — جاسوس(ها) فوراً برنده می‌شوند.

### رفتار گروهی و ایمنی

- **ربات باید ادمین گروه باشد** — تا قبل از ادمین شدن، دستورات و دکمه‌ها کار نمی‌کنند (برای تشخیص خروج اعضا و پاک کردن پنل‌ها لازم است).
- **خروج بازیکن از گروه**
  - لابی: از لیست حذف می‌شود؛ اگر سازنده برود، لابی حذف می‌شود.
  - حین بازی: کنار گذاشته می‌شود؛ خروج آخرین جاسوس → برد شهروندان؛ کمتر از حداقل بازیکن فعال → تساوی.
  - حین حدس نهایی: اگر جاسوس اخراج‌شده برود → برد شهروندان.
- **گرفتن ادمین از ربات یا حذف ربات از گروه** — بازی/لابی زنده پاک می‌شود تا گروه گیر نکند.
- **ریست ادمین** — ادمین گروه می‌تواند `/deletecurrentgame` بزند و state بازی فعلی همان چت را پاک کند.
- **ضد اسپم** — محدودیت کوتاه روی دکمه‌ها و دستورات سنگین (`/newgame`، `/deletecurrentgame`، `/start`).
- **تایمر و بازیابی** — تایم‌اوت لابی، دور، رأی و حدس نهایی؛ بعد از ری‌استارت، با مهلت‌های ذخیره‌شده در Redis دوباره هم‌تراز می‌شود.

### عملیات

- **State زنده فقط روی Redis** — برای اجرای بازی امروز به دیتابیس نیاز نیست.
- **لاگ JSON ساخت‌یافته** در stdout، `logs/app.log` و `logs/error.log` (با rotation).
- پشتیبانی **Docker** برای توسعه و استقرار.
- **لیست کلمات** — فایل قابل ویرایش `data/words.txt`.

## شروع سریع (Docker)

1. مخزن را کلون کنید و وارد پوشهٔ پروژه شوید.

2. فایل محیط بسازید:

   ```bash
   cp .env.example .env
   ```

   حداقل این را تنظیم کنید:

   ```env
   BOT_TOKEN=your_bot_token_here
   ```
   اگر در ایران هستید پورت پروکسی socks5 خودتون رو هم وارد کنید :
   ```env
   TELEGRAM_PROXY=http://host.docker.internal:yoursock5port
   ```
3. سرویس‌ها را بالا بیاورید:

   **توسعه** (hot-reload، پورت Redis، mount لاگ):

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.local.yml up --build -d
   ```

   **در production:**

   ```bash
   docker compose up --build -d
   ```

4. ربات را به یک **گروه تلگرام** اضافه کنید، **ادمین** کنید، سپس `/newgame` بزنید.

## پیکربندی

مقادیر از متغیرهای محیطی خوانده می‌شوند (نگاه کنید به `.env.example`).

| متغیر | پیش‌فرض | توضیح |
|--------|---------|--------|
| `BOT_TOKEN` | *(الزامی)* | توکن ربات تلگرام |
| `TELEGRAM_PROXY` | — | آدرس اختیاری پروکسی برای API تلگرام (پایین را ببینید) |
| `REDIS_HOST` | `redis` | نام میزبان Redis |
| `REDIS_PORT` | `6379` | پورت Redis |
| `REDIS_DB` | `0` | ایندکس دیتابیس Redis |
| `MIN_PLAYERS` | `3` | حداقل بازیکن برای شروع |
| `MAX_PLAYERS` | `10` | سقف لابی |
| `SPY_THRESHOLD_PLAYERS` | `7` | آستانهٔ تعداد برای دو جاسوس |
| `LOBBY_TIMEOUT_SECONDS` | `300` | حذف خودکار لابی اگر شروع نشود |
| `VOTING_TIMEOUT_SECONDS` | `60` | مدت فاز رأی‌گیری |
| `FINAL_GUESS_SECONDS` | `30` | مهلت حدس نهایی جاسوس بعد از اخراج |
| `REDIS_GAME_TTL_SECONDS` | `3600` | TTL ایمنی کلیدهای بازی در Redis |
| `THROTTLE_CALLBACK_SECONDS` | `0.7` | حداقل فاصله بین کلیک دکمه برای هر کاربر |
| `THROTTLE_COMMAND_SECONDS` | `3.0` | حداقل فاصله برای دستورات سنگین |
| `LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `LOG_DIR` | `logs` | پوشهٔ فایل‌های لاگ |
| `LOG_MAX_MB` | `20` | حداکثر حجم هر فایل لاگ (مگابایت) |
| `LOG_BACKUP_COUNT` | `3` | تعداد نسخه‌های چرخشی هر فایل |

### پروکسی تلگرام (`TELEGRAM_PROXY`)

**فقط** وقتی از شبکهٔ شما تلگرام مسدود یا در دسترس نیست (مثلاً در برخی کشورها) استفاده کنید. در `.env` از حالت کامنت خارج کنید و مقدار بدهید:

```env
TELEGRAM_PROXY=socks5://host.docker.internal:1080
```

(یا هر URL از نوع HTTP/SOCKS که روی ماشین شما کار می‌کند).

- **Docker محلی:** در `docker-compose.local.yml` مقدار `host.docker.internal` طوری تنظیم شده که کانتینر به پروکسی روی هاست برسد.
- **Production:** استفاده از پروکسی **توصیه نمی‌شود**. تأخیر بیشتر، پایداری کمتر و نگهداری سخت‌تر می‌شود. بهتر است ربات جایی میزبانی شود که به تلگرام مستقیم دسترسی دارد.
- اگر بدون پروکسی تلگرام کار می‌کند، `TELEGRAM_PROXY` را خالی بگذارید.

متغیرهای مربوط به PostgreSQL ممکن است برای یک **قابلیت آینده** در پروژه باشند؛ برای اجرای فعلی ربات **لازم نیستند** (بخش [برنامهٔ آینده: تاریخچه و آمار](#برنامهٔ-آینده-تاریخچه-و-آمار) را ببینید).

## دستورات

| دستور | کجا | چه کسی | توضیح |
|--------|------|---------|--------|
| `/start` | خصوصی یا گروه | همه | معرفی / بررسی سلامت |
| `/newgame` | فقط گروه | همه (ربات باید ادمین باشد) | تنظیمات و ساخت لابی |
| `/deletecurrentgame` | فقط گروه | ادمین / مالک گروه | حذف اجباری بازی یا لابی فعلی این چت |

بقیهٔ کارها با **دکمه‌های اینلاین** است (پیوستن، خروج، شروع، رأی، نقش، تنظیمات).

---

## روند یک دور بازی

1. کسی `/newgame` می‌زند و تنظیمات را تأیید می‌کند.
2. بازیکنان به لابی می‌پیوندند؛ سازنده وقتی آماده بود (و حداقل نفرات جمع شد) شروع می‌کند.
3. نقش و کلمه تخصیص داده می‌شود. شهروندان با «دیدن نقش من» کلمه را می‌بینند؛ جاسوس فقط می‌فهمد جاسوس است.
4. بحث تا پایان تایمر دور ادامه دارد، مگر جاسوس زودتر کلمه را عیناً بفرستد و ببرد.
5. رأی‌گیری باز می‌شود. بعد از آرا (یا تایم‌اوت) کسی که بیشترین رأی را دارد حذف می‌شود.
6. نتیجه به نقش حذف‌شده و حدس نهایی بستگی دارد — یا تساوی بعد از دور دوم رأی مساوی.

## لیست کلمات

فایل `data/words.txt` را ویرایش کنید:

- هر خط یک کلمه، **یا** چند کلمه با کاما در یک خط
- خطوط خالی و خطوطی که با `#` شروع می‌شوند نادیده گرفته می‌شوند
- تکرار کلمه بین بازی‌ها مجاز است (تاریخچهٔ «کلمهٔ استفاده‌شده» per-group نگهداری نمی‌شود)

برای اعمال تغییر معمولاً نیاز به ری‌استارت پروسه است.

## لاگ‌گیری

- **stdout** — خطوط JSON (مناسب Docker)
- **`logs/app.log`** — از سطح `LOG_LEVEL` به بالا، با rotation
- **`logs/error.log`** — فقط خطاها، با rotation

پوشهٔ `./logs` را به کانتینر mount کنید (در فایل‌های Compose تنظیم شده) تا روی هاست باقی بماند.

## برنامهٔ آینده: تاریخچه و آمار

بازی‌های زنده همین الان کامل روی **Redis** اجرا می‌شوند. ذخیرهٔ دائمی بازی‌های تمام‌شده **هنوز فعال نیست**.

در به‌روزرسانی بعدی قرار است اضافه شود:

- ذخیره در **PostgreSQL** برای بازی‌های تمام‌شده (برنده، دلیل پایان، کلمه، بازیکنان، نقش‌ها)
- **آمار کاربر و گروه** (تعداد بازی، برد، دفعات جاسوس بودن و مشابه)
- در صورت نیاز، دستور یا پنل برای **نمایش آمار** در گروه یا چت خصوصی
- فعال‌سازی مدل‌های موجود در `app/models/` و مایگریشن‌های `migrations/`

تا آن زمان:

- نیازی به بالا آوردن سرویس Postgres نیست
- نتیجه در چت اعلام می‌شود ولی در دیتابیس بلندمدت نگه داشته نمی‌شود
- چک‌لیست کوتاه پیاده‌سازی در `TODO.md` است

## نکات توسعه

- state زنده در **Redis** است، نه فقط حافظهٔ پروسه؛ بعد از ری‌استارت می‌توان تایمرها را از روی مهلت‌های ذخیره‌شده بازیابی کرد.
- تا وقتی بازی در جریان است ربات باید **ادمین گروه** بماند؛ وگرنه تشخیص خروج و پاک کردن پنل‌ها قابل اتکا نیست.
